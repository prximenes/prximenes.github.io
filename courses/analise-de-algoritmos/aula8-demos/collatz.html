🌀 Sobe, desce… e sempre chega no 1?

Comece com um inteiro n > 0. Se ele é par, divida por 2. Se é ímpar, faça 3n + 1. Repita. A pergunta (Slide 12) é: esse processo sempre chega em 1? Ou seja, o programa collatz(n) do Slide 15 para para todo n? Ninguém sabe a resposta desde 1937.

funcao collatz(n):
  enquanto n != 1 faca
    se n mod 2 = 0:  n <- n / 2
    senao:           n <- 3*n + 1
  fim
  retorne 1

⏱️ “E se a gente esperar bastante?” O observador com relógio

Lembra da primeira tentativa de resolver o Problema da Parada: simular o programa e ver se ele para? Aqui o observador roda collatz(n) por no máximo K passos. Se chegar em 1, ele responde SIM. Se o tempo acabar, ele só pode dizer “não sei”: talvez falte só mais um pouco, talvez nunca termine.

💡 O que levar para a aula
Testar um caso é fácil. Para um n específico, basta rodar: se chegar em 1, a resposta é SIM (n = 27 leva 111 passos).
Testar muitos casos não é prova. Computadores já conferiram todos os n até cerca de 2⁶⁸ (≈ 3 × 10²⁰). Mesmo assim, ninguém provou que vale para todo n.
Esperar não decide. Se o programa ainda está rodando depois de K passos, isso não prova que ele nunca vai parar. É exatamente o problema do “simulador” na prova da indecidibilidade de HALT.
🔗 Conexão com o Problema da Parada
Um programa H que resolvesse HALT responderia, para qualquer n, se collatz(n) para.
Hoje nem os melhores matemáticos sabem responder isso para todo n. Na aula vamos ver algo mais forte: esse H não existe. Não é só que ainda não o encontramos: é impossível escrevê-lo.
Atenção: HALT ser indecidível não diz que Collatz é falsa nem que ela nunca será provada. Diz que não existe um único algoritmo que responda a pergunta da parada para todos os programas.
